# Godot 特效系统 V2 设计规范

这份文档是 `godot/` 原生特效升级的共同基线。浏览器端不属于本规范的目标运行时；后续特效开发默认使用 Godot 4.7.2、CanvasItem 和原生 GPU shader。

## 1. 核心目标

V2 特效服务于三个目标：

1. **命中立刻有反馈**：玩家在一眼和一个短音效周期内知道哪里发生了什么。
2. **短平快且有层次**：特效快速出现、快速完成、自然收尾，不用慢速大圆环或长时间悬浮装饰拖住画面。
3. **状态和冲击分开**：击碎瞬间是一次性演出，被影响砖块的状态是持续表现，两者不能混成一个僵硬的循环动画。

V2 的手感关键词：

> 触发快、峰值高、轮廓清楚、收尾干净、连锁不糊。

## 2. 已验证的风格

### 2.1 爆炸砖：白热火团

爆炸不是简单的圆环和放射线，而是由独立的 GPU 火焰体组成：

- 白热闪燃。
- 火团扩张。
- 压力波和场景轻微位移。
- 火星、碎片和烟尘快速消散。

实现位置：

- `godot/src/render/bomb_blast.gdshader`
- `godot/src/render/bomb_batch.gd`
- `godot/src/effects/effects.gd::bomb_blast()`

爆炸砖和技能共用该入口及 16 事件预算，1.1s 收尾。`explosions.gd` / `explosion()` 仅保留用于旧火团回归和性能对照，生产技能不得再调用；以 `native_explosion_test.gd` 的真实技能触发检查防止回退。

关键方法：

- 用 `ShaderMaterial` + 有界 `MultiMeshInstance2D` 承载程序化火团、冲击环和碎片。
- 用分层轮廓、径向距离和时间包络生成火焰形状。
- 用独立视觉时间 `fx.visual_time` 驱动动画。
- 在共享 GPU mesh 中绘制火星和碎片，保留明确的方向与重力。
- 爆炸事件脱离物理砖块生命周期，砖块删除后仍能完整播放。

### 2.2 冰冻砖：瞬时冰爆 + 持续冰层

冰冻效果经过多轮迭代后采用两段式结构：

**瞬时冲击层**：

- 极短白蓝闪击。
- 少量短距离冰晶碎片。
- 碎片轻微旋转、外弹、下坠。
- 不使用闭合圆环，不使用跨越整个棋盘的长射线。

**持续状态层**：

- 被冰冻砖块表面覆盖一层半透明晶体薄膜。
- 冰层内部有不规则晶面、裂纹、噪声和移动高光。
- 冰层从冰砖方向生长，保持目标关系。
- 血量数字、特殊图标和砖块颜色仍然可读。

实现位置：

- `godot/src/render/frost.gdshader`
- `godot/src/render/frost.gd`
- `godot/src/core/brick.gd`
- `godot/src/core/simulation.gd`
- `godot/src/effects/effects.gd::frozen_target()`

重要经验：

- 扩散承载层必须足够大，不能让 shader 被正方形或圆形几何边界硬裁切。
- 冰层和一次性冲击不能共享同一个大范围扩散动画。
- 长射线很容易破坏画面结构，冰晶碎片应使用世界坐标限制飞行距离。

### 2.3 电弧砖：短促跳电

电弧使用 CanvasItem 多层折线绘制：

- 8 条不同长度的主弧和短弧。
- 粗蓝色外辉。
- 高亮主体。
- 白色电流内芯。
- 主弧中段产生短分叉。
- 中心使用白热闪核。

当前目标节奏约为 `0.42s`，但效果峰值集中在前半段。电弧可以很夸张，但不能变成长时间 beam，也不能遮蔽整个棋盘。

实现位置：

- `godot/src/effects/effects.gd::special_break()`
- `godot/src/render/board.gd::_draw_special_breaks()`

### 2.4 金钱砖：金币爆闪

金钱砖使用高对比、强识别度的金币爆发：

- 中心大金币徽章。
- 深色外缘、亮色金币面和内部 `¥` 印记。
- 四角金色闪芒。
- 10 个金色或浅金色碎片向外弹出。
- 碎片带轻微下坠，短距离完成后消失。

当前目标节奏约为 `0.58s`。金币特效的重点是“奖励感”和“可读性”，不能只画小粒子或低对比金色圆环。

## 3. 动画节奏规范

### 3.1 默认时间段

除非特效本身需要更长的玩法提示，否则采用以下范围：

| 阶段 | 建议时长 | 作用 |
| --- | ---: | --- |
| 触发闪击 | 0.02 - 0.08s | 让命中瞬间有重量 |
| 主体爆发 | 0.08 - 0.28s | 展示核心形状和方向 |
| 碎片/分叉 | 0.18 - 0.42s | 增加爽感和材质反馈 |
| 收尾消散 | 0.35 - 0.75s | 避免突然消失 |

特效总时长建议：

- 普通特殊砖击碎：`0.30 - 0.65s`。
- 大型爆炸：`0.80 - 1.40s`，但主体峰值必须更早出现。
- 持续状态层：可以超过上述范围，但必须低强度、低对比、不会阻塞后续命中。

### 3.2 时间曲线

优先使用“快起、快峰、慢尾”的包络：

- 出现使用 `smoothstep` 或指数上升。
- 主体强度使用快速衰减，例如 `exp(-age * 6~30)`。
- 碎片使用短距离外弹和重力，不使用匀速无限远飞行。
- 收尾应由 alpha、尺寸、亮度分别衰减，避免整层同时突然消失。

避免：

- 半径达到上限后停住。
- 闭合圆环一直保持固定粗细。
- 从中心发出贯穿整块棋盘的直线。
- 所有元素同时出现、同时消失。
- 只用 `sin()` 循环脉冲伪装成动画。

## 4. 渲染分层

一个完整的 V2 特效通常分为四层：

### A. 冲击核心

负责第一帧的命中确认：白闪、热核、冰核、金币徽章中心等。

特点：短、亮、集中，通常在 `0.10s` 内完成峰值。

### B. 主体形状

负责识别特效是什么：火团、跳电、冰晶、金币等。

可以使用 shader 或 CanvasItem，但必须保留清晰轮廓。

### C. 材质细节

负责让特效看起来有材质：噪声、晶面、裂纹、内芯、外辉、金币边缘等。

材质细节不能替代主体形状；主体不清楚时，先扩大轮廓和对比度，再增加细节。

### D. 场景响应

负责让效果和场景发生关系：

- 爆炸附近砖块的短暂偏移和暖色染色。
- 冰冻目标按距离结冰。
- 电弧末端和分叉产生瞬时闪点。
- 金币碎片朝奖励感方向外弹或上扬。

场景响应必须是视觉状态，不能修改物理边界、碰撞结果或伤害时序。

## 5. 技术选型

优先程序化 shader 与 CanvasItem 动态几何，尽量避免贴图。特效应有明确的生成、运动和消散过程，不以静态图标的缩放、旋转代替冲击与材质变化。

### 5.1 使用 GPU shader 的场景

适合：

- 大面积连续体，例如爆炸火团、烟尘、冰层薄膜。
- 需要噪声、流动、溶解或局部高光的材质。
- 多个实例使用同一形状，只改变位置、时间、seed、颜色和强度。

当前范例：

- `bomb_blast.gdshader`
- `frost.gdshader`

shader 必须：

- 使用明确的时间包络。
- 不依赖屏幕截图或 CPU 纹理上传。
- 处理好承载几何边界，避免方形裁切。
- 为 reduced motion 提供低成本、视觉等价的降级。

### 5.2 使用 CanvasItem 的场景

适合：

- 少量折线、分叉、碎片、火星和硬轮廓。
- 需要世界坐标中的方向、重力和精准位置。
- 需要根据事件数组绘制不同长度或不同数量的元素。

当前范例：

- 电弧的折线和分叉。
- 金币碎片。
- 冰冻后的冰晶碎片。
- 爆炸火星。

### 5.3 使用 retained board 的场景

砖块本体仍由 retained board 绘制。持续冰层、爆炸染色和瞬时偏移必须放在独立动态层，不要让每帧变化的效果导致所有砖块重新生成 retained 节点。

## 6. 状态和事件接口

玩法状态和视觉事件必须分离：

- `brick.frozen`：玩法状态，影响伤害和后续判定。
- `brick.frost_born`、`brick.frost_direction`：仅用于表现，不写入存档。
- `fx.specials`：短生命周期的一次性砖块事件。
- `fx.bombs`：爆炸砖和技能共用的 GPU 爆炸事件，砖块删除后仍然存在。
- `fx.visual_time`：所有展示动画的统一时钟。

新增特效推荐提供独立方法，例如：

```gdscript
func special_break(point: Vector2, type: String, intensity: float = 1.0, depth: int = 0) -> void
func frozen_target(point: Vector2, radius: float = 42.0) -> void
func bomb_blast(point: Vector2, radius: float = 132.0, intensity: float = 1.0) -> void
```

不要在 renderer 中反推玩法事件，也不要让 renderer 直接修改砖块血量、类型或碰撞状态。

## 7. 性能和预算

### 7.1 必须有界

- 粒子：最多 300 个。
- 一次性特殊事件：最多 48 个。
- 爆炸 GPU 实例：最多 16 个。
- 电弧、金币、冰片等单事件元素数量应保持个位数到十几个。
- 事件溢出时优先淘汰最旧视觉事件，不影响玩法。

### 7.2 随机数

视觉随机只能使用 `g.visual_rng` 或事件 seed：

- 不能消耗玩法 RNG。
- 相同游戏种子下，玩法结果必须保持一致。
- 特效事件应保存 seed，而不是保存大量随机点。

### 7.3 reduced motion

开启 reduced motion 或性能模式时：

- 减少碎片数量和分支数量。
- 禁用或降低场景位移、旋转和高频噪声。
- 保留一次短闪、主体轮廓和最终状态。
- 不得因为降级而丢失“命中了什么、影响了什么”的信息。

## 8. 颜色和可读性

颜色优先从主题 palette 获取；临时高光可以使用固定的材质色，但必须在浅色和深色主题下都能读清。

建议的层级：

- 主体色：特殊砖主题色。
- 内芯：白色或接近白色。
- 外辉：主体色向亮色偏移。
- 阴影/边缘：主体色向深色偏移。
- 状态层：低 alpha，不覆盖血量和图标。

在预览中至少检查：

- 浅色主题。
- 深色主题。
- 特殊砖旁边有普通砖的密集场景。
- 连锁同时触发多个特效的场景。

## 9. 新特效升级流程

每升级一种残留特效，按以下顺序执行：

1. 确认玩法触发点和事件生命周期。
2. 定义 0.3 - 0.7 秒内的主节奏和峰值帧。
3. 先画出核心轮廓，确认一眼可读。
4. 再添加材质层、碎片和场景响应。
5. 决定哪些层使用 shader，哪些层使用 CanvasItem。
6. 为 reduced motion 和事件数量设置上限。
7. 添加对应的生命周期/预算测试。
8. 用浅色、深色和连锁预览检查；每批完成后必须生成真实 Godot 渲染的循环 GIF，打开并在交付回复中附动图链接，不能仅用静态截图代替。
9. 跑原生测试和 `git diff --check`。

### 动图快速工具

```bash
python3 godot/tools/preview_effects.py --skills shatter execute rage aftershock
python3 godot/tools/preview_effects.py --skills shatter execute rage aftershock --theme dark --reduced
python3 godot/tools/preview_effects.py --skills execute --speed 0.5 --seconds 2.2
python3 godot/tools/preview_effects.py --list
```

- 依赖 Godot **4.7.2 stable**、Python Pillow，以及可用显示环境或 Xvfb；无需 ffmpeg。
- 默认每批最多 4 个技能，25 fps、原速、2.2 秒循环，包含触发前停顿和消散尾段。`--fps`、`--seconds`、`--speed`、`--theme`、`--reduced` 和 `--out xxx.gif` 可调整。
- 默认保存到 `agent-tmp/godot/effect-gifs/`，同目录保留渲染日志与参数 JSON。临时 PNG 帧自动清理。
- 工具使用真实 Board / CanvasItem / GPU shader 和固定步长视觉时钟逐帧采集；GIF 只用于展示，不是游戏运行时贴图。
- 新增特效时在 `godot/tools/effect_previews.json` 注册技能 ID、事件时长、完整尾段和类型。普通事件使用 `skill_event`，共用爆炸技能使用 `explosive_skill` 的真实玩法入口；其他持续场、弹道等效果需补对应的采集场景，不能伪装为已有模板。
- 独立特效展示不替代真实技能触发测试。检查生成动图的峰值、尾段、循环间隔、标签与主题可读性后，向用户交付 GIF 路径或内联动图。

## 10. 验收清单

一个 V2 特效完成前，应满足：

- [ ] 命中第一帧有明确反馈。
- [ ] 主体在密集砖块中仍然可见。
- [ ] 没有固定半径停住的圆环或硬边裁切。
- [ ] 没有长时间拖尾或无意义循环。
- [ ] 一次性冲击和持续状态层彼此独立。
- [ ] 砖块血量、图标和类型仍可识别。
- [ ] 特效不修改玩法状态和物理边界。
- [ ] 视觉随机不消耗玩法 RNG。
- [ ] 事件和粒子数量有明确上限。
- [ ] reduced motion 仍保留核心信息。
- [ ] 浅色和深色主题均完成预览。
- [ ] 有对应原生测试覆盖生命周期、队列上限和 reset。

## 11. 当前参考实现

| 特效 | 入口 | 渲染实现 | 节奏 |
| --- | --- | --- | ---: |
| 爆炸砖 / 爆炸技能 | `Effects.bomb_blast()` | 共用固定 16 实例 GPU 爆炸：冲击环、火团、火舌、碎块、火星、烟团与场景响应 | 约 1.1s |
| 冰砖冲击 | `Effects.special_break()` | GPU 中心冰闪 + 合批冰片 | 约 0.56s |
| 被冰冻砖块 | `Effects.frozen_target()` + brick frost state | GPU 冰层薄膜 | 持续状态 |
| 电弧砖 | `Simulation.hit()` → `Effects.skill_event("storm")` | 复用雷神降临逐跳 GPU ribbon，无旧放射层或重复 bolt | 0.5s/跳 |
| 金钱砖 | `Effects.special_break()` | 合批金币徽章 + 真字体 ¥ + 金色碎片 | 约 0.58s |

- `godot/tests/native_explosion_test.gd`
- `godot/tests/native_frost_test.gd`
- `godot/tests/native_special_brick_test.gd`
